# 11 · Known drift

> **What you need from this chapter**
>
> - The places where a document, a name or a design file says one thing and the code does another.
> - Which of those are deliberate, so you do not "fix" them.
> - Where drift tends to come back, and the rule for settling it.

The agent docs, the skills and `DESIGN_SYSTEM.md` were reconciled with the code on 2026-10-07. What is
left below is either deliberate or a naming quirk to know about.

## The rule

When two sources disagree, the code on `main` wins, then `tokens.css`, then `DESIGN_SYSTEM.md`, then
the agent notes (see the [README](README.md#when-two-sources-disagree)). Fix the document, or report
the mismatch; do not change the code to match a stale document.

## Deliberate, leave alone

| Looks like drift                                                                                    | Why it is right                                                                                             | Where to look                                       |
| --------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| `--font-weight-extra-light` is `200`, but `fonts.css` loads Inclusive Sans for weights 300–700 only | the weight scale does not depend on one font: a project that swaps the font family keeps a real extra-light | `text/font-weight.tokens.json`, `fonts.css`         |
| some primitive colours have a `hex` note that does not exactly match their OKLCH value              | those colours are outside the sRGB range, so any hex is an approximation; the OKLCH value is what renders   | `palette/color.tokens.json`                         |
| `gv-tooltip` sits on a **summit** surface, while its Figma component still uses aurora              | the code is deliberately ahead of the design file; aurora is a transient highlight, not a resting surface   | `Tooltip.ts`, `DESIGN_SYSTEM.md` (elevation rule 8) |
| `pnpm check-ledger` fails on `main`                                                                 | a component added since the last release has no ledger entry yet; the next release records it               | chapter 09                                          |
| Storybook's a11y checks report violations but never fail                                            | report-only until known issues are fixed; the canary proves the checks still work                           | `.storybook/preview.ts`, chapter 08                 |
| `package.json` has a higher version than npm                                                        | the version was bumped in a branch and the release has not been published yet                               | `pnpm view @edgarjaymez/grove version`              |

## Naming quirks

| What the name suggests                                               | What it does                                                                                                       | Where to look                        |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------ |
| `pnpm test:unit` runs the unit tests                                 | it runs `vitest` in watch mode over **every** project; `pnpm vitest run --project unit` runs only the unit project | `package.json`                       |
| `src/lib/components/index.ts` is how components get into the package | the package entry is `src/lib/index.ts`; nothing imports the components barrel, which is kept by convention        | `vite.config.ts` (`build.lib.entry`) |
| a metadata `component.version` is the package version                | it is the component's own version, bumped when that component changes                                              | any `*.metadata.ts`                  |
| the root `README` is the project readme                              | it is an essay on systems thinking; setup lives in this guide                                                      | `README`                             |

## Where drift comes back

- **`DESIGN_SYSTEM.md` after token changes.** It is prose, and nothing tests it against `tokens.css`.
  When you change a token, search the doc for its name.
- **`src/.ai/`** after component changes. It is regenerated by hand by the maintainer, so it can lag a
  few changes behind.
- **Agent notes** (`CLAUDE.md`, `AGENTS.md`, `.claude/`). They are gitignored and edited outside the
  normal review flow.
- **Figma.** Designs and annotations can describe a state the code has moved past, as with
  `gv-tooltip` above.

If you find new drift, note what the document says, what the code does, and the file that proves it,
and raise it with the maintainer.
